01 // Microservice Architecture

CropDoc AI is a production-grade inference service fine-tuned on the PlantVillage dataset under strict engineering constraints to guarantee reproducibility, thread safety, and sub-300ms latency stability on standard CPU servers.

The microservice is designed following a clean layered architecture: FastAPI Router Layer → Inference Service Layer → Model Loader Layer & Preprocessing Transforms Layer → Fine-Tuned PyTorch ResNet18.

Performance Targets

  • • Latency Target: <300ms on CPU (~42ms avg)
  • • Deterministic Thread-Safe Transforms
  • • SHA-256 Dataset Verification Hash
  • • Warmup Model Singleton Lifecycle

02 // Engineering & Architectural Safeguards

Safeguard 01

Thread-Safe Single-Load Transform

Torchvision transform pipeline is initialized exactly once during FastAPI startup (`lifespan` event) and stored globally, eliminating concurrency race conditions and request-time overhead.

Safeguard 02

Model Singleton & Startup Warmup

The fine-tuned ResNet18 model is loaded onto the CPU, set to `model.eval()`, and pre-warmed with a dummy forward-pass on boot to eliminate initial invocation latency spikes.

Safeguard 03

CPU-Optimized Determinism

Inference execution leverages `torch.inference_mode()` (improving over standard `torch.no_grad()`) for peak CPU performance.

Safeguard 04

Collision-Proof Dataset Hashing

Dataset integrity is verified via a SHA-256 hash computed over canonical, sorted identifiers: `f"{global_index}:{label}:{unique_dataset_id}"`.

03 // Architecture Decision Record (ADR)

ADR-003 // CPU-Bound Lifespan Model Singletons Status: Accepted

Context: Instantiating PyTorch image normalization pipelines or reloading model weights per incoming HTTP POST request causes severe CPU memory churn and non-deterministic response delays.

Decision: Bind ResNet18 model state and torchvision transforms to global memory singletons managed by FastAPI's `@asynccontextmanager` lifespan handler, executing `torch.inference_mode()` on CPU tensors.

Consequences: Eliminates runtime allocations, stabilizing sub-50ms CPU inference while preserving thread safety under concurrent requests.

04 // Inference Latency Bound Formulation

Total API response latency $T_{\text{inference}}$ is upper-bounded to guarantee low-latency edge server compliance:

$$T_{\text{inference}} = T_{\text{transform}}(I) + \underset{\theta}{\operatorname{forward}}(X) \quad \text{where } T_{\text{inference}} < 300\text{ms (CPU)}$$

05 // REST API Endpoints

GET /health

Returns service status (`{"status": "ok"}`).

GET /model-info

Returns active model metadata, framework details, input size (`224x224`), and total disease classes (`15`).

POST /predict

Accepts `multipart/form-data` leaf images (JPEG/PNG $\le 5\text{MB}$) and returns predicted disease class, confidence score, top-k probabilities, and inference latency.
