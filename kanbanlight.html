01 // System Concept & Vision

Traditional Kanban software operates on single, destructive global state. If team members refactor sprint cards or reorder backlogs, there is no isolated sandbox to experiment with structural changes before committing to main.

KanbanLight brings the power of distributed version control, time-travel state hydration, sandboxed WebAssembly plugins, and a real-time developer CLI directly to project management.

Users can spin up board branches (e.g. experimental, sprint-2), visually diff card additions, modifications, and deletions, and merge changes back to main seamlessly.

02 // Core "Magic" Capabilities & Diffs

Feature 01

🌿 Time-Travel State & Branching

Create isolated board state branches without affecting main. Complete state snapshots (cards, columns, event logs) are serialized to IndexedDB for instant time-travel switching and hydration.

Feature 02

🔍 Visual Git Diffs

Compare your current active branch against target branches with tri-color indicators:

  • + Added: Green ring & tint for newly created cards
  • ~ Modified: Amber ring & tint for edited or moved cards
  • - Deleted: Red dashed ring & ghosted cards
Feature 03

💻 Developer CLI (`kb`)

Control the web UI directly from your terminal using a lightweight local WebSocket bridge (ws://localhost:8080). Run terminal commands and observe live UI reactivity.

Feature 04

🧩 Browser WebAssembly Plugins

Persist compiled .wasm binaries directly in IndexedDB (Uint8Array). Plugins auto-recompile on startup via WebAssembly.compile without backend server dependencies.

03 // Architecture Decision Record (ADR)

ADR-002 // Non-Destructive Event-Sourced Branching Status: Accepted

Context: Single-state Kanban boards force immediate destructive mutations when planning sprint structural overhauls, eliminating room for safe experimentation.

Decision: Persist each board branch as a distinct event-log array and serialized JSON document in IndexedDB (`board_branch_`), resolving branch deltas dynamically in the Zustand UI store.

Consequences: Enables instant non-destructive branch switching, visual diff computation, and CRDT synchronization without global state contamination.

04 // State Set Difference Formulation

Differential resolution between the active branch $B_{\text{active}}$ and target branch $B_{\text{main}}$ is formulated using set-theoretic delta matching:

$$\text{State Diff: } \Delta(B_{\text{active}}, B_{\text{main}}) = \{(c, \text{type}) \mid c \in (B_{\text{active}} \cup B_{\text{main}}), \, \text{type} \in \{\text{ADDED}, \text{MODIFIED}, \text{DELETED}\}\}$$
